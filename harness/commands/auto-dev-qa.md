# `/auto-dev-qa`

Run and receipt the project-configured QA gates as a standalone step. Use
`$auto-dev-qa`; unavailable infrastructure is evidence, not a passing result.
When `autodev.json` carries a Rules Engine context selection, use its frozen
status and any concrete artifact/snapshot evidence it names; do not replace it
with a live lookup. `kit-unavailable` and `insufficient-evidence` remain QA
limitations, not loaded-kit claims.
