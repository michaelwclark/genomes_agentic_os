# OS Context Audit

Use when a room, workflow, automation, or customer OS feels too broad, noisy, or hard for agents to load safely.

## Procedure

1. Identify the task or room being audited.
2. List read-first, read-when-needed, and do-not-load sources.
3. Check source priority and authority.
4. Check whether tool/skill routing is task-specific.
5. Flag context that belongs in references, templates, examples, archive, or source maps instead of active room files.
6. Record suggested edits without rewriting hand-authored runtime files unless explicitly requested.

## Output

Return findings by severity, files to load, files to skip, proposed moves, approval risks, and validation steps.
