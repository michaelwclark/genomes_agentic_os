# Archive Soon: Auto-Dev Migration Ledger

This is the item-by-item migration authority for overlapping Auto-Dev
capabilities. It is not permission to delete a working surface. Every row must
retain unique judgment or transport behavior until its replacement passes the
listed verification and retirement gate.

## Status key

| Status | Meaning |
| --- | --- |
| `CANONICAL` | Owns the behavior and is not a retirement candidate. |
| `KEEP ADAPTER` | Retains one bounded source, provider, validation, or trigger capability but no competing workflow state or policy. |
| `MIGRATE` | Unique behavior still needs to move behind the canonical owner. |
| `COMPATIBILITY` | Accepts existing callers/runs only; it must not start new canonical work. |
| `BLOCKED: INSTALL` | Source behavior exists, but installed/library/harness parity is not proven. |
| `BLOCKED: DECISION` | Retirement shape needs an operator choice. |
| `INVENTORY` | Exact callers, active runs, or external projections still need enumeration. |

`Verification` is the minimum parity proof for that row. `Retirement gate` is
the additional condition that must be true before an old name, file, workflow,
or state engine can be archived.

## Canonical ownership

| Mission | Canonical owner | Boundary |
| --- | --- | --- |
| SDLC operator experience | Auto-Dev program and its stage skills | Routes intent and composes policy; owns no second task state machine. |
| Delivery state and recovery | Development Delivery | Owns portfolio/task state, work items, worktrees, leases, transitions, and delivery receipts. |
| Bug and RCA investigation | Auto-Dev Detective | Owns request, version gate, source manifest, evidence, analysis, pause/resume, and conclusion state. |
| Artifact quality and provider shape | Auto-Dev Create Artifacts | Owns provider/type contracts, render, validation, apply handoff, and readback contract. |
| Idea/spec lifecycle | Spec Engine | Owns intent, grooming, lifecycle, and source work; delegates provider rendering. |
| Domain evidence and transports | Routed domain programs | Supply bounded evidence or actions; never create competing Auto-Dev state. |

## Migration protocol

Every `MIGRATE`, `COMPATIBILITY`, or blocked row must complete all applicable
checks before its status changes:

- [ ] Replacement command/skill works manually from a fresh Claude and Codex chat.
- [ ] Equivalent natural-language intent routes to the replacement without the
      user naming Auto-Dev.
- [ ] Root/domain/project/invocation policy parity is proven by fixtures and a
      representative live or provider-sandbox sample.
- [ ] Active state resumes, or a migration receipt maps every state, decision,
      receipt, external identity, and unresolved blocker.
- [ ] Registries, `TOOLS.md`, dashboards, schedules, docs, and Genome's Notion
      point to the canonical owner.
- [ ] The old surface contains a compatibility breadcrumb and rollback note.
- [ ] One defined observation window shows no unique invocation or output.
- [ ] Retirement receipt names archived paths, retained history, validation,
      rollback, owner, and date.
