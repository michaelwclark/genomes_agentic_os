# LOS QA Automation Ticket-Family Delivery

This is the `los_qa_automation` QA-stage policy. It owns focused test delivery
after `los_app_los_django` has classified and opened the child assessment.

For a Playwright-automatable assessment, create a QA contract with the tenant,
target/build, personas, Playwright path/tags, required capability, and expected
root-Jira transition. Analyze the application diff, acceptance criteria,
existing QA coverage, and the QA repository's analysis skill before selecting
test files.

Use LOS Stage Demo Loans only for idempotent non-production base users,
relations, and loans. Use a registered `los_test_data` provider for reference
data, document packages, and lifecycle state. Route native product
configuration or rules through LOS Configuration Change; do not conceal those
changes in a fixture packet. Every mutable prerequisite requires plan, approved
apply, and independent semantic verification.

Use a focused feature branch and QA-only pull request. Run static checks,
discovery, targeted tests, and the smallest justified hosted tier. Once merged
under this project's policy, run the hosted workflow at the merged exact
revision against the intended tenant/build. Evidence from another tenant, build,
or old PR head is not passing evidence.

For a non-browser or blocked assessment, record a typed decision and required
alternative validation. Do not manufacture a Playwright scenario. Return the
child outcome and receipts to the `los_app_los_django` parent; that project owns
the root Jira transition.
