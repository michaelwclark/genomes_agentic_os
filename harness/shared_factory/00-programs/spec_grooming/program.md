# Program: spec_engine

## Purpose

Provide one policy-driven lifecycle for ideas, tickets, backlog items, features,
bugs, and configuration changes, from raw intent through verified delivery.

## Aliases

- `/groom-spec`
- `/add-spec`
- `spec-engine`
- `spec-groomer`
- `spec_grooming` (legacy program id and directory)
- universal spec grooming
- idea-to-spec grooming

## Owner

Shared Agentic OS product surface.

## Scope

This program owns:

- canonical status and type semantics;
- layered root/domain/project/invocation policy;
- filesystem, Linear, and Jira adapter contracts;
- original intent capture and iteration deltas;
- capability discovery before net-new work;
- route decisions across existing programs, workflows, skills, and projects;
- A-plus packet shape for product, technical, QA, rollout, state, and Gherkin;
- tracker and documentation projection rules;
- idempotent sync receipts and adapter health.

This program does not own:

- implementation orchestration after a packet is ready;
- provider-specific team ceremonies;
- auto-merging, PR checks, or deployment;
- making Notion a mandatory queue or lifecycle owner.

## Status

Active canonical OSProgram. The `spec_grooming` path and id remain supported as
compatibility aliases during migration.
