# Start here

This section is for someone who has never used this system before. It explains
what each part is for and where it applies, in ordinary English, before naming
any of the internal vocabulary.

If you are already operating the system and want detail rather than
orientation, skip to the [handbook](/docs/) or the
[command reference](/docs/17-cli-reference).

## Read in this order

1. **[What this actually is](./what-this-is.md)** — the problem it solves and
   who it is for. Ten minutes, no setup required.
2. **[Install it](./install.md)** — get the command-line tool and create your
   first OS folder.
3. **The seven ideas** — one short page each. Read them in order; each one
   builds on the last.

## The seven ideas

Almost everything in this system is one of seven things. Learn these and the
rest of the documentation stops being confusing.

| Idea | One sentence |
| --- | --- |
| [Domains and projects](./domains-and-projects.md) | The top-level folders that separate your different areas of work. |
| [Work items](./work-items.md) | One folder per piece of work, holding everything about it from start to finish. |
| [Workflows](./workflows.md) | A written-down procedure you follow more than once. |
| [Automations](./automations.md) | A workflow that has earned the right to run without you starting it. |
| [Runs and receipts](./runs-and-receipts.md) | The record of what actually happened, kept so you can check it later. |
| [Hosts](./hosts.md) | The individual computers the system runs on. |
| [Command Center](./command-center.md) | The desktop app for looking at all of the above. |

## Two things to know up front

**Everything is files.** There is no server to log into and no hosted account.
The system is a folder on your own computer, full of Markdown and YAML files.
You can open any of it in a text editor, search it with `grep`, and put it in
version control. If the command-line tool disappeared tomorrow, your work would
still be readable.

**It is shared between you and your AI agents.** The point of writing the work
down in a fixed structure is that a coding agent — Claude, Codex, or a human
picking up where you left off — can read the same folders and know where things
stand. Nobody has to re-explain the project at the start of every conversation.
