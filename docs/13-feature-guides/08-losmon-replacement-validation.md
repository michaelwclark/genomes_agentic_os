## Status

Feature 08 was removed from the product. The `agentic-os losmon validate`
command no longer exists, and `agentic-os --help` no longer lists a `losmon`
subcommand. Installed OS roots that still contain artifacts generated by the
old command keep working; only the generator is gone.

## What This Feature Was

The feature scaffolded a read-only validation package for one specific
migration: evaluating whether an installed OS root could take over the work of
LOSMon, a personal automation service. It pre-created a project, three
engineering and operations workflows, a support automation, placeholder run
logs closed as `waiting`, and a comparison artifact listing the gaps the old
system still covered.

Because the command hardcoded that single migration, it was personal-product
scaffolding rather than a reusable capability, and it was removed when the
product defaults were de-personalized.

## How To Cover The Same Ground

A migration-validation package is a composition of surfaces that still exist.
To evaluate whether an OS root can replace an existing automation stack:

1. Create a project for the migration with `agentic-os project create` and
   record the candidate repository with `--repo`
   ([guide 01](01-project-create-and-active-work.md)).
2. Create one workflow per process you want to prove out with
   `agentic-os workflow create`, and review readiness with
   `agentic-os workflow check`
   ([guide 03](03-workflow-readiness-and-run-closeout.md)).
3. Create automations at `observe` maturity with `agentic-os automation create`
   and attach them to the project
   ([guide 04](04-automation-maturity-and-reconfiguration.md)).
4. Record read-only trial runs with `agentic-os run-log create` and close them
   with explicit validation evidence
   ([guide 03](03-workflow-readiness-and-run-closeout.md)).
5. Keep a comparison artifact in the project `artifacts/` folder listing what
   the old system still does better, and do not remove entries until real
   validation evidence exists.

## Source History

The implementation lived in `src/genomes_agentic_os/losmon.py` with CLI wiring
in the old monolithic `cli.py`. Both were deleted; inspect the history with:

```bash
git log --all --oneline -- src/genomes_agentic_os/losmon.py
```

Installed OS roots may still hold the historical spec and worklog folders under
the installed project's canonical `work-items/` lifecycle and
`worklogs/source-features/08-losmon-replacement-validation/`. They describe the
removed feature and are safe to archive.
