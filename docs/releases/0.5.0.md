# Genomes Agentic OS 0.5.0

This release adds a practical continuity mode for a personal two-host Agentic
OS installation: genomesbox remains the shared primary, while bigmac can keep
its own automations moving locally during a genomesbox outage.

## Genomesbox-primary personal fallback

- `remote_with_local_fallback` uses the authenticated genomesbox control plane
  during normal operation.
- A separate bigmac watchdog probes readiness once per minute and activates
  only after three consecutive failures by default.
- Activation latches bigmac onto its existing durable local SQLite queue. The
  latch survives process and host restarts.
- Work already admitted by genomesbox stays in its PostgreSQL ledger and waits
  for recovery. The fallback never guesses whether an uncertain remote submit
  committed and then duplicates it locally.
- Primary recovery is reported, but never triggers automatic failback. The
  explicit failback command first proves genomesbox readiness.

This mode favors understandable personal continuity over consensus-grade high
availability. It does not claim automatic shared-ledger takeover, zero data
loss, or network-partition fencing.

## Explicit standalone genomesbox primary

The shared genomesbox control plane can now run under
`standalone_primary`, a signed but deliberately non-HA authority. Both the
canonical policy and protected host runtime must opt in the exact genomesbox
host ID. The co-located witness renews short-lived proofs and permanently
rejects promotion and failback. The control plane also reads PostgreSQL's own
settings before admitting mutations: it must be a local primary, use
`synchronous_commit=local` or `on`, have no synchronous standby target, and
retain `fsync`, full-page writes, and WAL archiving.

This permits ordinary tasks, effects, and schedules on genomesbox without the
hourly degraded-primary deadline. It grants no shared-ledger authority to
bigmac; bigmac's continuity remains its local fallback queue.

First bootstrap is runner-governed and one-shot: witness readiness and durable
SQLite/sentinel proof are required before a host completion marker is written,
then the witness is recreated with bootstrap disabled before the primary
starts. Standalone policy rotation is supported as a fail-closed local
maintenance transaction without changing leader or epoch. The HA-only
artifact-replication timer stays disabled in personal mode so an intentionally
absent standby does not generate permanent false alarms.

## Operator commands

```bash
agentic-os runtime fallback status --json
agentic-os runtime fallback probe --apply --json
agentic-os runtime fallback activate --reason maintenance --apply --json
agentic-os runtime fallback failback --apply --json
```

Standalone authority is a separate exact-host opt-in:

```yaml
standalone_primary:
  enabled: true
  host_id: genomesbox
```

The macOS deployment assets can activate only the lightweight watchdog:

```bash
activate-macos.sh --apply --personal-fallback
```

The watchdog uses the canonical `runtime.execution_fabric.health` alert route,
so outages and recovery state flow through Agentic OS and desktop notification
instead of becoming another private monitoring island.

## Configuration

The single root-level `harness/config/execution-fabric.yml` remains the queue
policy owner. Personal fallback adds only discoverable transport policy:

```yaml
transport:
  mode: remote_with_local_fallback
  control_plane_url: http://100.64.0.2:3180
  fallback:
    failure_threshold: 3
    state_path: harness/shared_factory/00-control-plane/execution-fabric-fallback.json
```

The state file is mutable host-local runtime state, not configuration and not a
secret. Host identities, routing, and alert destinations remain in their
existing canonical registries.

## Immutable deployment images

The release image lock now contains all seven runtime images: control plane,
leadership witness, worker, PostgreSQL, Valkey, MinIO, and the MinIO client.
Release CI resolves the four reviewed third-party source tags to multi-arch
index digests and the asset builder accepts only each canonical
`repository@sha256:digest` reference. A mutable tag, missing image, or repository
substitution stops the release.

The JSON lock is also the single input for runtime and emergency-bundle
materialization. A strict installer helper emits all seven `FABRIC_*_IMAGE`
entries, including witness and worker, while bundle validation regenerates the
projection and rejects any mismatch. The portable emergency archive embeds the
same released JSON lock.

## Upgrade

Install the 0.5.0 assets on both hosts, configure genomesbox with the explicit
standalone-primary policy/runtime and co-located signed witness, configure
bigmac with the fallback transport and scoped remote credentials, then activate
the bigmac personal-fallback watchdog. Keep the replicated standby, promotion,
and failback stack inactive unless you later choose to adopt consensus-grade
HA.
