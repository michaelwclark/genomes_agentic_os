# Genomes Agentic OS 0.4.2

This patch release makes the Execution Fabric leadership and recovery path
portable, fail-closed, and observable while tightening the release contract
that ships it.

## Portable leadership authority

- Run the independent leadership witness as a digest-pinned OCI image on a
  dedicated third host outside the two execution candidates.
- Persist leadership state, audit history, and signed receipts in durable
  SQLite with explicit first bootstrap and closed failure on missing,
  incomplete, or corrupt initialized state.
- Commit each authority transition and its replayable receipt before local
  database promotion. Concurrent requests have one durable winner, and a retry
  after response loss receives the original result.
- Bind the witness to an operator-selected private address, isolate state and
  prepared secrets behind protected mounts, and supervise health with a
  systemd timer that emits canonical Agentic OS alerts.

When an independent third host is unavailable, use `manual_fail_closed`. That
mode starts no witness and requires automatic failover and promotion to remain
disabled; the two execution candidates never act as their own quorum.

## Installation and recovery corrections

- Immutable installation remains inert until a separate, preflight-gated
  activation step. Repeated activation is idempotent.
- Compose recovery commands preserve paths containing spaces, and PostgreSQL
  replication slots follow the host they feed.
- Datastore credentials remain in protected files rather than rendered runtime
  configuration.
- Backup health requires a successful restore into a disposable database, not
  merely a completed dump command.

## Release integrity

- One validator now checks the Python package and lock record, runtime module,
  both Node packages and npm lock roots, worker Helm chart, and static release
  manifest for the same version.
- Release tags must be reachable from `main`, existing release assets cannot be
  overwritten, and CI exercises a real witness image start, durable readiness,
  and restart.
- The release workflow publishes digest-pinned control-plane, witness, and
  worker images plus the image lock, manifest, configuration bundle, emergency
  bundle, software bill of materials, Python distributions, and checksums.

## Artifact compatibility

Cross-host task reports continue to use the S3-compatible artifact protocol,
including MinIO endpoints. Artifact storage and leadership authority remain
separate operational concerns.

## Upgrade

Install from the immutable image digests and verified assets attached to the
release. Installation does not enable failover. Keep automatic promotion
disabled until the independent witness, protected credentials, database
restore, bidirectional artifact replication, alert delivery, and documented
promotion/failback drills all have fresh readback receipts.
